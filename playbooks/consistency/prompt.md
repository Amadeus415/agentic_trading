# Consistency

Semantically identical or logically linked outcomes can carry inconsistent prices across dates, strikes, outcomes, or venues.

Code already trades exclusive NO baskets mechanically in the baseline fund. Spend research on what code cannot verify: cross-venue flags, threshold ladders (a higher strike priced above a lower one), date ladders (an earlier deadline priced above a later one), and events whose mutual exclusivity is unknown. Verify equivalent rules and settlement sources literally. Account for each leg, fees, depth, and non-atomic execution. Never call a textual match arbitrage.

Estimate p_win as the probability that the purchased outcome settles at $1, and record the same belief in YES terms (p_yes) in the session forecast file. Forecast every market you research, including those you would not trade: forecasts are how this playbook earns trust. Sizing keeps only the measured share of your disagreement with the market, so state honest probabilities, never inflated ones. Prefer contracts that resolve soon; capital that turns over compounds. State a realistic horizon through settlement, shared event driver, falsifier, and uncertainty. Refresh every existing position. Python owns fees, sizing, and fills. Exclude contracts that merely predict a stock or crypto price. Preserve failed research as a blocker, never cash evidence.
