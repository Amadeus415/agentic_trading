# Scheduled prediction-market research

Research and reviews run as headless Claude Code sessions (`claude -p`) started by launchd, like the monitor. Each run opens a fresh session in the runtime checkout, follows this file, and stops. No app needs to be open. The model-free monitor is a separate LaunchAgent.

## The tasks

From the runtime checkout, run `./scripts/install_claude_tasks.sh` once. It installs two LaunchAgents that call `scripts/run_claude_task.sh`, which reads the prompt below from this file. Times are Pacific.

| LaunchAgent | Schedule | Prompt |
| --- | --- | --- |
| `com.edgecraft.claude-research` | Daily 07:15, 10:15, 12:15, 18:15 | [Research prompt](#research-prompt) |
| `com.edgecraft.claude-review` | Sundays 17:15 | [Review prompt](#review-prompt) |

The four research times land in four different UTC session slots, so each gets its own cycle key. Runs fire only while the Mac is awake. After sleep, launchd starts one catch-up run for the missed times, and the cycle key keeps a late run from repeating a session that already succeeded. A run that finds another Claude session still going skips. Each session's transcript is in `state/logs/claude-<task>-<UTC time>.log`.

Sessions use `--permission-mode auto` so an unattended run never waits on a prompt, and `--strict-mcp-config` so no account connectors (mail, calendar, drive) load. The runtime's `.claude/settings.json` installs a PreToolUse hook that denies broker order tools in every session, whatever the permission mode. The installer copies `CLAUDE_CONFIG_DIR` from your shell so sessions use your logged-in account. To run one session now: `launchctl kickstart gui/$UID/com.edgecraft.claude-research`.

## One packet, one apply

1. Run `./scripts/prepare_local_runtime.sh` offline. Trading/review runs never pass `--update`. Stop on unresolved preparation or integrity failure.
2. Discover paths with `rg --files` or Glob. Read `make -s EDGECRAFT=.venv/bin/edgecraft fund-context`. Schemas are under `input_contract.decision_schema`, `input_contract.quote_schema`, and `forecast_contract.schema`; `forecast_skill` shows each playbook's measured trust. Complete a due review under [EVOLUTION.md](EVOLUTION.md), then refresh context.
3. Run `make EDGECRAFT=.venv/bin/edgecraft fund-scan`. Both venue listings are required. Inspect bounded coverage, exclusions, and individual failures. A failed required source or missing position mark is terminal, not evidence that cash is attractive. Never bypass TLS verification or denied access.
4. Research in rank order: `catalysts` (resolving within 48 hours) first, then the highest-ranked `candidates`. Rank favors contracts that resolve soon and that few traders watch; `annualized_if_wins` shows what a correct call earns per year of capital. Work all three playbooks: resolution reading, consistency (`cross_venue_flags`, strike and date ladders; `event_flags` baskets are already traded by the code-only baseline), and long-tail news. Read exact settlement rules and primary sources. Similar question text is only a review hint. Check dates, timezones, exclusions, and dispute risk. Exclude stock/crypto price bets.
5. Write the session forecast file next to the packet: `state/fund-inputs/<cycle key>.forecasts.json`, shaped by `fund-context`'s `forecast_contract` (`uv run edgecraft fund-forecast-schema`). Forecast every market you researched, traded or not, 30 or more when the scan allows, as `p_yes` with `variant` set to the playbook or experiment ID and a `category`. When a review has created experiment versions, forecast the same markets under the parent and each child so they compete head to head. Code stamps each forecast with its own market price; never supply one. Record it at once with `make EDGECRAFT=.venv/bin/edgecraft fund-forecast FORECASTS=state/fund-inputs/<cycle key>.forecasts.json`, so the forecasts count even if a later step stops the session. A recording failure is not terminal; report it.
6. Run `fund-snapshot` for every open position and researched instrument. Use its returned quotes, not guessed cache files. Instrument arguments are `--instrument polymarket:<id>:YES:prediction` or `--instrument kalshi:<ticker>:NO:prediction`. Refresh candidate books immediately before the decision; cached scan quotes may have become stale.
7. For each directional belief, state `p_win` as probability the purchased outcome settles at $1, playbook ID, shared-event driver, target, invalidation, source evidence tagged with that contract's instrument ID in `instrument_ids` (Python drops beliefs whose evidence names only the event), and a realistic horizon through resolution (maximum 8,760 hours). Buy YES or NO with cash. Do not short. Target/stop success is not the definition of `p_win`. Journal every open or ordered instrument and researched rejected candidates. Python shrinks each `p_win` toward the market by the playbook's measured trust, drops edges below the annualized hurdle, funds the fastest edges first, and owns every quantity. Be decisive: give a long belief on the favored side for every researched contract where your honest `p_win` beats the ask, even by a few points, and aim for 10 or more beliefs a session. Never mark a positive-edge belief flat or pull `p_win` toward the market out of caution. Trust shrinkage and the caps already own risk, so hedging your own number discounts it twice.
8. Save one complete packet to the `input_path` printed by `fund-context` or `fund-cycle-key`. It must use that UTC session key, fresh decision time, and unchanged source timestamps. Include runtime model and prompt version when known. Never invent evidence, fees, quotes, or quantities.
9. Run `./scripts/run_scheduled_cycle.sh` exactly once. It records any forecasts not yet recorded, verifies, applies with code-owned quotes and belief sizing, verifies again, and writes the v2 chart and report.
10. Inspect `make fund-show`, `make fund-verify`, and `make fund-report-file`. Report simulated fills/settlements, cash, exposure, NAV, provenance, forecast trust, and blockers honestly. No routine publishing or tracked-file commits are part of research runs.

Before packet creation, missing paths, parser mistakes, or no search matches in read-only discovery are recoverable: correct the inspection and continue. Unresolved preparation/integrity failures, incomplete required research, missing position marks, packet validation failures, and any failed apply are terminal. Once saved, do not rewrite a packet to pass a gate. Do not retry failed applies or reuse a stopped key; use a fresh future session after the blocker is fixed. Only identical, explicitly permitted access recovery is allowed.

## Sessions

Keep the existing UTC slots for idempotency: 13:00–15:59 `session-eu`, 16:00–18:59 `session-us-open`, 19:00–22:59 `session-us-close`, otherwise `session-offhours`. Keys are `YYYY-MM-DD-<slot>`. These are legacy names for research windows; prediction trading does not depend on equity hours. The model-free five-minute monitor and the code-only baseline fund have their own timestamped keys.
